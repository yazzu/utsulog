# 投稿日時フィルターと「前後5分を表示」コマンド 設計

## 概要

現在の検索フィルターは「投稿日(日付単位)」のFrom/To指定のみをサポートしている。これを「投稿日時(時刻単位)」に拡張し、あわせて検索結果カードから「そのチャットの前後の文脈を見る」ためのショートカットコマンドを追加する。

元要件: `docs/feature-search_by_dateterm.md`

## 背景・目的

配信の正確な時刻を覚えていて手動でFrom/Toに入力する使い方は稀である。本命の使い方は「検索結果のカードから、その発言の前後で何が起きていたかを見る」こと。したがって:

- 手動のFrom/To時刻入力は最小限の実装に留める(既存の日付inputに任意の時刻inputを添えるのみ)。
- カードからの「前後5分を表示」コマンドを主機能として設計する。手動の時刻inputは、このコマンドが設定した期間を表示・微調整するための画面としても機能する。

## スコープ

**含む**
- サイドバーのFrom/To日付フィルターに、任意の時刻inputを追加。
- From/To投稿日時が両方揃った場合、検索ワードなしでもその期間で検索する。
- 検索結果カードから「前後5分を表示」を実行できる(時計アイコン)。
- 実行後、期間の手動微調整、元の検索への復帰。

**含まない**
- 時刻帯だけを繰り返し条件にする機能(例: 毎日22時〜23時)。
- 前後の分数(5分)をユーザーが変更できるUI(将来拡張の余地はあるが今回は固定5分)。

## UI/UX仕様

### サイドバーのFrom/To日時フィルター

- 既存の `<input type="date">` (From/To) はそのまま維持。
- 各日付inputの隣に、任意の `<input type="time">` を追加(`timeFrom`, `timeTo`、初期値は空文字)。
- 時刻が未入力でも日付のみでこれまで通り機能する(デフォルト補完は後述)。

### 検索トリガー条件の変更

`debouncedSearch` 冒頭のearly-return条件(`frontend/src/App.tsx:149`)に、「`dateFrom` と `dateTo` が両方とも設定されている」場合を追加する。検索ワード・投稿者名・動画選択のいずれもない状態でも、日時範囲が両方揃っていれば検索を実行する。

### カードの「前後5分を表示」コマンド

- 各検索結果カードの `elapsedTime` バッジの下に時計アイコンを追加する(元要件のplan2)。
- タップすると確認なしで即座に以下を実行する:
  1. 現在の検索条件一式(`searchQuery`, `dateFrom`, `timeFrom`, `dateTo`, `timeTo`, `authorName`, `selectedVideoId`, `messageType`, `sortOrder`)をスナップショットとして保持する。
  2. 以下をセットする。
     - `searchQuery` → `''`
     - `authorName` → `''`
     - `messageType` → `'all'`
     - `selectedVideoId` → そのカードの `videoId`(同一動画内に限定)
     - `dateFrom`/`timeFrom`, `dateTo`/`timeTo` → そのカードの投稿日時(`result.timestampSec`、epochミリ秒)の `-5分`(`-5*60*1000`ミリ秒) 〜 `+5分`(`+5*60*1000`ミリ秒)
     - `sortOrder` → `'asc'`(時系列順に固定。会話の流れとして読めるようにするため)
  3. 検索結果セクションの直前に sticky なバナーを表示する。
     - 文言: 「期間表示中: `MM/DD HH:MM` 〜 `MM/DD HH:MM`」(実際に適用中のFrom/Toを表示。手動で範囲を微調整しても表示が破綻しない汎用的な文言にする。「前後5分」のような固定文言にはしない)
     - 右側に「元の検索に戻る」ボタンを配置。
- ユーザーはサイドバーのFrom/To(日付+時刻)を通常通り編集でき、既存の `debouncedSearch` の依存配列により自動的に再検索される。追加の実装は不要。
- 「元の検索に戻る」ボタンは、手動で微調整した後でも、直前に保存したスナップショットへ全state(検索条件一式)を復元する。

### バナーのsticky表示

- バナーは無限スクロールの対象コンテナである `<main className="overflow-y-auto">` の直下(検索結果セクションの直前)に配置する。
- CSSの `sticky top-0 z-10`(背景色付き)を指定し、JSでのスクロール追従処理は追加しない。

## データフロー

### 日時結合ロジック(フロント→API)

検索実行直前に、`dateFrom`+`timeFrom` と `dateTo`+`timeTo` を結合して完全なISO日時文字列を組み立て、`date_from`/`date_to` としてAPIに送る(実装アプローチ案A)。

秒の補完は「時刻が未入力かどうか」に関わらず、常に固定ルールで行う(FromとToに同じ時刻が明示入力された場合でもゼロ幅の範囲にならないようにするため):

- `date_from` の秒 → 常に `:00`
  - 時刻未入力時: `00:00:00`
  - 時刻入力時(例 `22:00`): `22:00:00`
- `date_to` の秒 → 常に `:59`
  - 時刻未入力時: `23:59:59`
  - 時刻入力時(例 `22:00`): `22:00:59`

「前後5分を表示」コマンドが自動セットする日時も、この結合ロジックを経由して同じ関数で処理する(特別扱いしない)。

### 「前後5分を表示」実行時のstate遷移

1. スナップショット保存(現在の全検索条件state)
2. 前後表示用stateへ切替 → 検索実行(`reset=true`)
3. (任意)サイドバーで手動微調整 → 通常の検索フローで再検索
4. 「元の検索に戻る」→ スナップショットを全stateへ復元 → 検索実行(`reset=true`)

## API仕様変更(`api/main.py`)

- 対象箇所: `api/main.py:200-214` の `date_from`/`date_to` 処理ブロックのみ。他のフィルター(`author_name`, `video_id`, `message_type`)は変更なし。
- リクエスト契約: `date_from`/`date_to` は常に完全なISO日時文字列(例 `"2026-07-10T22:00:00"`)として受け取る前提に変更する。
- 境界値ロジック:
  - `date_from` → `datetime.fromisoformat()` でパースし `range.gte` にそのまま使う。
  - `date_to` → `datetime.fromisoformat()` でパースし `range.lte` にそのまま使う(現行の `+ timedelta(days=1)` + `lt` のハックは廃止)。
- パース失敗時は現行同様、当該フィルターを付与せず無視する(`try/except ValueError: pass`)。

## エラーハンドリング

- 日時パース失敗時: 該当フィルターを付与しない(現行踏襲)。
- 「前後5分を表示」実行時、対象カードの `timestampSec` が欠損しているケース: 検索結果には必ず含まれるフィールドのため、特別なエラー処理は設けない。
- 前後5分の範囲が配信の開始直後・終了直前にかかり結果が少ない/0件になる場合: 既存の「検索結果が見つかりませんでした」表示をそのまま使い、特別扱いしない。

## テスト方針

- **API**: `date_from`/`date_to` の境界値テスト。`gte`/`lte` が意図通りに機能し、`+1日` ハックが完全に除去されていることを確認する。
- **フロントの日時結合ロジック**: `dateFrom/timeFrom/dateTo/timeTo` → ISO文字列への変換を純粋関数として切り出し、ユニットテストする。
  - 時刻未入力(From/To両方)のケース
  - From/Toに同じ時刻を明示入力したケース(秒固定補完によりゼロ幅にならないこと)
- **前後5分を表示ボタンの状態遷移**: スナップショット保存→前後表示への切替→「元の検索に戻る」で復元、を確認する。
- **手動確認**: スマホ幅のブラウザで、日付+時刻inputの並び、時計アイコンのタップ、stickyバナーの追従を確認する。
