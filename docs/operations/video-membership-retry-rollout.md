# 会員判定取得の再試行修正（2026-09-14）

初回定期実行で会員判定が1,094件未判定となった。既存の確定フラグ1,091件は保持されたが、HTTP失敗と解析失敗が同じ根拠コードだったため、朝の直接原因は確定できない。動画保存ログには429があり、夜の少数確認では取得に成功した。

この修正はbatchのみ。API・frontend・ES mappingの変更は不要。

- 匿名動画ページへのリクエスト開始間隔は最低2秒。再試行にも適用する。
- 1動画あたり最大3試行。429は60秒・120秒、5xxと通信例外は5秒・10秒を基準に待機する。
- `Retry-After`の秒数・HTTP日時を尊重する。待機要求が300秒を超える場合や429が3試行続く場合、その回の収集を中断し、早すぎる再要求を行わない。
- HTTPステータス、タイムアウト、通信障害、解析失敗を区別する。URL・認証情報・例外本文は診断ログへ出さない。
- 未確定が5件連続、または20件以上処理した時点で失敗率25%以上なら停止する。配信待機画面（`watch_player_offline`）は未確定を維持するが、通信障害の閾値には数えない。
- 25件ごとの進捗と最終集計を出す。収集が停止した場合は従来のatomic replaceに到達せず、共通NDJSONは維持される。定期バッチの`set -e`により後続処理へ進まない。
- 会員判定不能をfalseにせず、ESへの部分更新時は従来どおり過去の確定値を保持する。

検証はモックによる再試行・待機・異常停止・旧ファイル保持と既存契約の回帰テスト、その後に配信待機3件・対象2件・今朝失敗した動画を含む40件の実取得と部分投入を行う。40件の確認は全件取得時に制限を受けない保証ではない。

1,364件では間隔だけで約45分必要になる。翌朝の定期実行で全件の結果と失敗集計を確認する。再び閾値停止した場合、短時間で再実行せずログのHTTPステータス・失敗理由を確認する。認証によるアクセス制限の回避は行わない。

切り戻しでは対象cronを停止する。追加フィールドとAPIの絞り込みは維持する。旧収集器には大量失敗時も継続する問題があるため、旧SHAに戻してcronを自動再開しない。
